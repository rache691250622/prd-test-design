# 多设备交叉并发

## 触发条件

PRD 同时满足以下条件时，必须建立 `CC-*` 并发契约清单：

- 同一主体可在两台或以上设备保持有效操作态。
- 操作按每个请求自身的“本机”决定保护范围，或可对其他设备执行单项操作。
- 存在批量撤销、退出、禁用、删除等会改变共享主体状态的操作。

## CC 清单

在 `03-需求规格.md` 中为每种交叉组合建立稳定标题。每项至少记录来源、参与设备、每个请求的本机视角、同步点、待验证终态和待确认语义。

```markdown
### CC-001

| 字段 | 内容 |
|---|---|
| PRD 来源 | [SRC-006](#src-006) |
| 参与设备 | M、D1，均为账号 A 的有效会话 |
| 请求 1 | M 发起一键撤销；M 是请求 1 的本机，批量范围不含 M |
| 请求 2 | D1 撤销设备 M；D1 是请求 2 的本机，目标为 M |
| 同步点 | 两端均加载操作前设备状态后，同时提交请求 |
| 待验证终态 | M/D1 会话、设备/授权记录、审计与响应提示 |
| 待确认语义 | PRD 未定义时，确认 M、D1 最终是否均失效及响应语义 |
| 追踪 | [SPEC-020](#spec-020)；[RULE-018](04-业务规则.md#rule-018) |
```

## 最小组合矩阵

为每类受影响账号设计下列组合；使用全文一致的设备示例标识，写清账号归属、会话身份及各请求的本机视角，不要求真实设备已经搭建。

| 组合 | 请求 1 | 请求 2 | 关键点 |
|---|---|---|---|
| CC-A | M 一键操作 | D1 单项操作 M | 两端均将对方视为非本机；不得只验证 M 的请求 |
| CC-B | M 单项操作 D1 | D1 一键操作 | 与 CC-A 方向相反，防止仅一侧实现正确 |
| CC-C | M 一键操作 | D1 一键操作 | 两个批量范围各自排除本机，校验交叉影响 |

“一键操作”应替换为 PRD 中的具体动作，如一键撤销、一键退出或批量禁用。只有 PRD 明确支持的动作才能进入正式用例。

## 用例规则

并发 TC 的前置条件必须声明：账号、M/D1 的有效态、两端都已获得操作前状态，以及同步提交机制。步骤必须分别从两个客户端发起操作，不能写成先后点击。

每个组合必须观察：

1. M 与 D1 的最终会话是否有效，且结果符合已确认的产品契约。
2. 两台设备对应的授权/设备记录是否到达唯一终态，未回滚、未重复创建、未出现相互覆盖。
3. 每个请求的成功、失败或幂等响应是否与最终状态一致，不出现“成功但目标仍有效”等矛盾提示。
4. 审计、通知和失效事件是否最多产生一次，或符合明确的幂等规则。
5. 账号 B 的会话与记录完全不受影响。

PRD 仅说明“批量操作不影响本机”时，不能推导出两个交叉请求后哪台设备应保留有效态。先将该终态写入待确认项；获得产品或后端契约后，再生成带确定预期的正式 TC。
