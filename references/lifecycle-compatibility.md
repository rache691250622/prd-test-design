# 生命周期与历史数据兼容

## 触发条件

PRD 出现以下任一表述时，必须建立 `LC-*` 清单：

- 功能上线前后、版本升级前后、灰度前后。
- 数据迁移前后、回填、历史记录、旧数据、存量数据。
- 曾经登录/创建/操作，但之后未再登录/未再操作。
- 存量会话、旧 Token、缓存、旧客户端或历史接口。

## LC 清单

在 `03-需求规格.md` 中为每条生命周期事实建立稳定标题和表格：

```markdown
### LC-001

| 字段 | 内容 |
|---|---|
| PRD 来源 | [SRC-004](#src-004) |
| 边界前状态 | 功能上线前，设备 H 已登录账号 A，旧登录态仍有效。 |
| 边界事件 | 设备登录记录能力上线。 |
| 边界后行为 | H 上线后从未再次登录，因此未被新登记能力写入设备记录。 |
| 当前可观察结果 | H 不在列表，但一键撤销仍须失效其旧登录态。 |
| 追踪 | [SPEC-014](#spec-014)；[RULE-013](04-业务规则.md#rule-013) |
```

每条 `LC-*` 必须映射到一个或多个 SPEC、RULE、POINT、SCN、TC；若 PRD 仅提出待确认能力，仍保留 `LC-*`，并标记为待确认，不得静默删除。

## 用例规则

生命周期 TC 的前置条件和测试数据必须分别表达：

1. **边界前**：数据或会话在哪个版本/时间点形成。
2. **边界后**：哪些新能力没有作用于该对象，例如“上线后未再登录”。
3. **当前状态**：为什么对象不在新列表、却仍具有可操作或兼容价值。
4. **验证动作**：当前功能如何处理该对象。

禁止将上述条件压缩为“历史设备 H 有有效态但无记录”。这种描述无法区分冷启动旧数据、数据被删除、接口漏写或普通未枚举对象。

## 示例

```markdown
## TC-019

**前置条件**：设备 H 在功能上线前已登录账号 A，旧登录态仍有效；功能上线后 H 从未再次登录，设备记录服务中不存在 H 的记录。

**测试数据**：
| 名称 | 值 |
|---|---|
| 上线边界 | T0 |
| H 首次登录 | T0 前 |
| H 上线后登录次数 | 0 |

**预期结果**：H 不在设备列表时，一键撤销仍失效 H 对账号 A 的旧登录态；H 下次登录必须重新身份验证。
```

## 评审检查

- 是否把版本或时间边界原样写入 TC 前置条件和测试数据？
- 是否验证“边界后未发生的动作”，而不只是当前对象状态？
- 是否能排除“数据被删”“接口漏登记”等非冷启动原因？
- 是否将生命周期事实同时写入规格、规则、场景和用例追踪？
