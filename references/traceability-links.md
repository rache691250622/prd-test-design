# Markdown 追踪链接

## 稳定锚点

每个正式 ID 都使用仅含 ID 的标题，避免标题变更影响锚点：

```markdown
### SPEC-001
玩家可以查看本账号的已授权设备记录。

### RULE-001
列表仅返回当前 UnionId 的已授权设备。

## TC-001
**标题**：查看已授权设备列表
```

不要使用 `### SPEC-001：设备列表` 或 `## TC-001：业务标题` 作为 `#spec-001` / `#tc-001` 的链接目标。用例编号使用独立二级标题，业务名称另放 `**标题**：...`。禁止用 `<a id="tc-001"></a>` 替代标题：Obsidian 的内部定位不保证识别 HTML 锚点，而仅检查该标签存在会错误放行。

编号标题在同一文件内必须唯一；链接使用小写 ID fragment，例如 `#tc-001` 对应原生标题 `## TC-001`。同文件和跨文件使用相同规则，业务标题改名不影响链接。来源引用也须指向真实标题；若原始 PRD 没有稳定标题，在需求规格中建立 SRC 条目并链接原文件，不修改 PRD 或创建仅 HTML 可见的跳转目标。

## 最小追踪格式

在每条场景和用例中使用可点击链接：

```markdown
**追踪关系**：
[ITEM-001](05-ITEM-POINT-拆分.md#item-001)；
[POINT-003](05-ITEM-POINT-拆分.md#point-003)；
[SCN-004](06-测试场景.md#scn-004)；
[RULE-005](04-业务规则.md#rule-005)；
[SPEC-002](03-需求规格.md#spec-002)
```

链接必须使用相对路径，确保整个版本目录被移动、压缩或提交 Git 后仍可跳转。不要在 Markdown 中写绝对本地路径或 `file://` 链接。

时序图布局中的主用例把 SCN 链接改为 `07-测试场景.md`；需要直接追踪程序交互时可追加 `[SEQ-001](06-时序图.md#seq-001)`。标准布局不得出现 `SEQ-*` 或指向不存在的 `06-时序图.md`。

## 链接质量门禁

运行 `scripts/validate_package.py --artifact <created-path>`。它检查生成文档中的内部链接目标文件、原生标题、重复 ID 和当前布局，忽略代码块与行内代码中的示例；HTML-only 目标、中文业务名称拼接标题却仍链接短 ID 的旧格式必须失败。标准布局和时序图布局都执行同一检查。原始需求快照不重写，生成文档指向它的链接仍须通过校验。

静态检查证明标题和链接对应；只有实际在 Obsidian 中点击过，才能报告动态跳转已验证。
