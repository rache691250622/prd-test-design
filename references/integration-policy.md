# 整合策略

## 来源优先级

| 等级 | 来源 | 可做什么 |
|---|---|---|
| 1 | PRD 正文、用户确认补充 | 创建或变更 SPEC、RULE、POINT、SCN、TC |
| 2 | 已选中 v9 主产物 | 作为补充基线，保留既有 ID 和结论 |
| 3 | 其他测试 Skill、历史用例、Excel | 提供候选覆盖，必须先映射到 PRD |
| 4 | 原型、截图、演示代码 | 仅辅助理解；PRD 未确认时记录待确认能力 |

## 差异唯一性判定

候选只有在以下至少一项与主用例不同且 PRD 有依据时才新增：

- 业务规则或来源规格。
- 触发入口或外部来源。
- 失败原因、异常恢复或未触发副作用。
- 权限边界、状态流转或数据一致性结果。
- 重要组合或可观察的数据断言。

仅替换设备型号、浏览器名称、城市、主题或时间样例不构成新增理由。

## 设计依赖与需求待确认

PRD 已定义外部交互行为时，保留有正式依据的用例，并在必要的前置条件或测试数据中写清依赖；实际环境、账号或工具尚未提供不影响设计交付。外部能力的业务语义未被正式需求确认时，列为需求待确认，不将推测写入正式预期。评审仅处理下列设计信息：

- 用例设计问题：来源、覆盖、条件、步骤或预期不完整、不一致，应修订用例。
- 测试准备条件：描述用例需要的账号特征、数据状态、时间条件及观测要求，不要求实际搭建、分配或验证，不另设环境检查或执行阻塞清单。
- 需求待确认：PRD 自身冲突或缺少验收口径，确认前不自行补写产品规则。

本 Skill 没有业务测试执行阶段，不根据资料分析或文档校验宣称发现已验证的产品缺陷，也不记录执行通过、不通过或环境阻塞状态。
