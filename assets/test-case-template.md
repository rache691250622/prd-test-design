# 测试用例模板

先阅读 `references/case-readability.md`。标题用一句简洁业务话表达“关键条件 + 操作对象及动作 + 核心可观察结果”，让不了解本功能的人知道测什么、怎么触发、如何判断。保留影响结果的因果边界，不用“正常处理、正确展示、功能验证”等含糊短语，不机械限制字数。简单用例看标题即可开展测试，复杂用例由正文交代执行细节。

写法示例（仅在需求已确认该规则时适用）：将“导入数量边界验证”改为“一次导入 101 个礼包，整份拒绝且不新增礼包”。追踪编号不能替代业务标题。下方占位内容必须替换为具体的用例设计信息，追踪示例和写作说明不复制到正式用例。“测试结果”任务框仅作模板预留，本 Skill 新生成用例时两项均不勾选，不增加执行阻塞字段。

### 前置条件

- 仅写必需的账号/权限、对象状态和时间/版本条件，一条一个短句；无特殊条件写“无”。
- 入口在此处或首步写一次；数据值和简短准备方法放测试数据，不重复功能背景或已完成的准备动作。

### 测试数据

| 名称 | 值 |
|---|---|
| 账号/对象 | 示例标识及必要的账号特征或业务条件，前置已写的权限/状态不重复；按需裁剪，不填写凭据，不要求真实账号已分配 |
| 输入/初始值 | 可直接使用的值，或简短、可复现的准备方法；保留决定结果的数量及时间/版本限定 |

| 步骤 | 操作 | 预期结果 |
